## Visibility rules

- **Flagship:** deepest maintained product with current public proof and a clear user loop.
- **Active:** maintained project with current repository-backed evidence.
- **Supporting:** reusable engine, library, tool, or companion that strengthens active projects.
- **Experimental:** prototype or alpha with explicit limitations and no inflated claims.
- **Private sandbox:** workflow or learning repository; do not expose private details publicly.
- **Archived:** historical work no longer actively maintained.

Remove a project from pins or primary profile sections when evidence is stale, the repository is archived, the current state cannot support the claim, or another project better represents the same skill.

## Mobile rendering checklist

- Best Places To Start appears before dense proof sections.
- Heading depth remains shallow and scannable.
- Disclosure blocks open without horizontal overflow.
- Code samples use short lines.
- Long links use descriptive labels.
- Tables are avoided when compact lists work.
- Screenshots contain no device-specific private data.
- Narrow GitHub app/browser views preserve proof and status language.
